# Native Full-Trajectory Comparison: Plan Commitment and Evidence Gate

## Conclusion

**The bounded candidate verifier did not improve complete-path optimality over the incumbent baseline in this five-task native execution pilot.** All three policies reached the task goal in all 10 RETAIN/SWITCH conditions. The candidate verifier achieved **5/10** reference-optimal full paths, the same as the incumbent baseline; the unrestricted classical graph first-action baseline achieved **7/10**. This negative result must be retained alongside the earlier positive first-action result.

The full graph planner was able to identify better first actions from the same public tool graph, yet the model sometimes diverged later and produced suboptimal complete paths. Consequently, **first-action replanning and continued plan execution are distinct evaluation targets**.

## Primary results

| Policy | Native goal reached | Reference-optimal full trajectory | Mean complete-path regret | Provider tokens |
|---|---:|---:|---:|---:|
| Force incumbent first action, then free continuation | 10/10 | 5/10 | 0.650 | 51,834 |
| Force bounded-gate first action, then free continuation | 10/10 | 5/10 | 0.563 | 75,028 |
| Force unrestricted graph-planner first action, then free continuation | 10/10 | **7/10** | **0.348** | 86,421 |

The complete-path regret is the realized native tool-path value minus the reference shortest feasible path value, counted only on goal-reaching paths. **Lower is better**. The graph baseline is an information-matched classical planning comparator, not another LLM-created proposal.

For all five RETAIN environments, all three policies selected and completed a reference-optimal path (5/5 per policy).

**Exact full-path optimum:** candidate-gate = 5 RETAIN + 0 SWITCH = **5/10**; incumbent = 5 RETAIN + 0 SWITCH = **5/10**; unrestricted graph = 5 RETAIN + 2 SWITCH = **7/10**.

The graph planner's selected **first actions** were optimal in all ten conditions of this fixed subset, but only seven of the **realized complete paths** were optimal. The difference is caused by subsequent, freely chosen DeepSeek actions. In particular, at Query00689 the initial switch is feasible and graph-favored, yet the model then takes a more expensive four-step continuation.

## What this establishes

1. On the prior 8 development and disjoint 10 confirmation tasks, the bounded gate showed a **75% balanced first-action accuracy**. This result is still valid as a checkpoint-local decision evaluation.
2. **This five-task full native execution pilot does not show a gain in the primary exact-full-path optimum count.** Completion is 100% for all methods and therefore not discriminatory here.
3. External tool-graph planning is already a strong comparator. On the frozen 10-task confirmation cohort, the unrestricted graph planner identifies the appropriate old-versus-new path for all 20 checkpoints *offline*; in real execution, subsequently unconstrained model decisions can forfeit optimality.
4. A plausible next research question is **state-aligned continuation**: after changing the first action, how does the Agent track the remaining plan, update it after each observation, and avoid drifting to an inferior continuation? This requires direct observation-based state checks and whole-path intervention studies, not merely another prompt asking the LLM to compare actions.

## Research limits

The five tasks were first seen in the previous independent first-action confirmation cohort, so they are **not untouched for the present full-path analysis**. They are disjoint from original mechanism-development tasks but are one task per category and only five base tasks. Actions for the first step were controlled via a restricted function interface in **all three** arms; subsequent calls were natural native model-tool interactions. Thus these results measure conditional execution once a given policy has selected a first action, not unconstrained model behavior at the original decision point.

The complete type/dependency graph and current tool values are fully visible to both the bounded gate and the unrestricted planner. This environment has a short-path planning structure, so the classical planner can be very strong without using the official reference solver API. There is currently **no evidence that the candidate-gate algorithm is better than an information-matched classical planner**.

## Decision

**NO-GO for promoting the current four-step candidate gate as a validated end-to-end replanning algorithm.** Keep it as an informative first-action decision baseline. Any next method must explicitly handle continued execution after the selected first action and demonstrate paired RETAIN/SWITCH gains in realized *complete* paths against a classical, information-matched planner, ideally on a separate task distribution.
